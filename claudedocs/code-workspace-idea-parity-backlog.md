### 3.1 维护者决策 2026-08-31：build gate 归属

ED-GATE-001 在 2026-08-31 记录了一个真实的依赖环：`pnpm build` 失败的 30 个 `error TS` 全部是 11 张 owner 卡的交付物，而这 11 张卡无一 claimable，其祖先又都把全仓 `build` 列为必需证据——例如 ED-SAVE-001 要 `done` 就要绿 build，绿 build 要修 `CodeWorkspaceTab.tsx` 的 4 个错误，那 4 个属 ED-STYLE-002，而 ED-STYLE-002 依赖链回到 ED-SAVE-001。53/66 张卡因此被封顶在 `implemented`。

已批准 Option 1 + Option 2 同时执行：

- **Option 1**：新增 **ED-GATE-003**（P0、`depends_on: []`），独家拥有全仓 TypeScript gate 与那 13 个文件的类型正确性；11 张 owner 卡保留各自的行为契约。
- **Option 2**：51 张功能卡的 `required_evidence` 把全仓 `build` 换成按路径界定的 **`typecheck`**（`scripts/typecheck_scope.py`），一张卡停工的模块不再拖住其余卡。全仓 `build` 此后只由 ED-GATE-003、ED-GATE-001、ED-QA-001 持有。
- Option 3（先推 ED-REL 链解锁）**未**采纳为解锁路径，ED-REL-001 仍是普通 P2 功能卡。
- ED-GATE-001 现 `depends_on: ["ED-GATE-003"]`，环被拆开而不是被隐藏。

`typecheck` 不是 `build` 的弱化版：范围只能按卡实际拥有的路径声明，不得为了避开自己的红文件而缩小，也不得用删断言、放宽封闭 union、`any` / `@ts-expect-error` 消错。详见 evidence-policy。

### 3.2 跨卡未解事实

- 完整 `pnpm test` 在 `6ec57e2a` 两次连跑计数不一致（run 1 = 2 failed / 3506 passed，run 2 = 1 failed / 3507 passed，共 390 files / 3508 tests），ED-GATE-001-A2 因此败在不确定性而非 build。稳定失败只有 companionCapabilities「builds plans that omit unsupported stages」（ED-STYLE-001 的 directory format scope 合同）；新发现的顺序相关失败是 CodeWorkspaceTab「sets mnemonic bookmarks…」，已纳入 ED-GATE-001 范围（单跑与 203 文件子集均绿，属测试隔离缺陷，不是书签行为缺陷）。
