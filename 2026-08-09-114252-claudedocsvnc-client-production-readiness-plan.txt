     Context

     The repository’s VNC client is functional but not production-ready on
     Windows 11. The current path is a synchronous Rust RFB engine
     (src-tauri/src/vnc/rfb.rs) running behind Tokio, an unauthenticated
     loopback WebSocket relay (ws.rs), and a monolithic React
     Canvas/input/clipboard component (VncPanel.tsx). The readiness document
     identifies connection hangs, insecure None preference, unbounded
     server-controlled allocations/decompression, missing relay authentication,
     incorrect resize behavior, unbounded queues, sensitive clipboard logging,
     ignored network settings, and missing real protocol/E2E coverage. The
     requested outcome is a Windows 11 client that is production-grade in
     behavior and performance, with every automatable validation completed; only
     tests requiring a real signed WebView2 package, physical DPI/IME/lifecycle
     conditions, or a real external VNC server/machine remain explicitly
     documented as manual.

     Scope and assumptions

     - Implement the shared protocol/session hardening needed by the Windows
     client: P0 transport/cancellation, structured errors/state, security policy
     (including safe None handling), resource limits, bounded relay,
     authenticated loopback, resize correctness, credential/log hygiene,
     lifecycle cleanup, and network/proxy/SSH-jump wiring.
     - Implement the Windows-facing P1 behavior that is testable in this
     environment: bounded frame flow/backpressure, complete input release
     behavior, clipboard policy and safe format handling, reconnect/backoff,
     diagnostics, DPI-independent remote-coordinate math, QuickConnect VNC
     routing, and detach handoff without putting a VNC password in browser
     storage.
     - Do not claim VeNCrypt/TLS, Tight/JPEG, native CF_HTML/RTF, or signed
     WebView2/DPI/IME/sleep validation as complete unless the repository’s
     current dependencies and an available fixture support them. If a feature
     cannot be implemented safely in this pass, make the limitation explicit in
     the UI/feature matrix and add a deterministic capability/error path rather
     than silently falling back.
     - Preserve compatibility with RFB 3.3/3.7/3.8, VNCAuth, RA2/RA2ne,
     Raw/CopyRect/Hextile/ZRLE, DesktopSize, legacy clipboard, and
     ExtendedClipboard.

     Implementation plan

     1. Establish shared contracts and limits

     - Add a VNC limits/policy module (for example src-tauri/src/vnc/limits.rs
     and policy.rs, exported from vnc/mod.rs) defining hard maximums for
     framebuffer dimensions/bytes, server strings/reasons, rectangle counts,
     compressed/decompressed rectangles, clipboard formats/decompressed totals,
     relay messages, and queue capacity. Use checked arithmetic and return
     typed, sanitized protocol errors.
     - Add structured session states and errors (stage, stable code, retryable,
     sanitized message) in the VNC module. Map all connect, handshake, auth,
     initialization, decode, clipboard, relay, timeout, and disconnect failures
     to this contract; keep raw socket/credential data out of user-facing errors
     and logs.
     - Add explicit security, input, clipboard, resize, and reconnect options
     with safe defaults. Default to rejecting None; support explicit
     allow-none/legacy-compatible behavior and report the negotiated RFB
     version/security/encryption state. Since VeNCrypt/TLS is not present today,
     require-encryption must fail with a dedicated unsupported-policy error
     rather than downgrade.
     - Add unit tests for policy strength ordering, None rejection/explicit
     allow, limit validation, checked-size calculations, state transitions,
     retry classification, and error sanitization.

     2. Replace blocking connection handling and wire network paths

     - Introduce an async transport abstraction for VNC, reusing
     src-tauri/src/rdp/transport.rs and src-tauri/src/terminal/network.rs for
     direct TCP, HTTP CONNECT, SOCKS5, IP-version choice, TCP options, and SSH
     jump/tunnel routing. Apply connection, handshake, authentication,
     initialization, read, write, and shutdown deadlines with cancellation-aware
     tokio::select!.
     - Port the RFB read/write helpers in rfb.rs to the async stream (or, if
     secure RA2 framing makes a complete port unsafe, isolate the synchronous
     implementation in a dedicated blocking worker with socket read/write
     timeouts and a cancellation-triggered shutdown). Do not execute unbounded
     read_server_message on a normal Tokio worker.
     - Keep reader and writer ownership independent; guarantee explicit
     disconnect closes both halves and the task group within two seconds. Make
     vnc_test_connection use the same transport, options, vault resolution, and
     timeout path as vnc_connect.
     - Add network_settings_json, policy/options JSON, and relevant session
     settings to the Rust command API, frontend IPC wrappers, tab types,
     MainLayout.openVncTab, detached VNC payloads, and VNC panel props. Resolve
     proxy sessions, proxy secrets, and jump credentials only in Rust, matching
     RDP’s rdp_connect flow.
     - Add transport tests for direct/local fixture, timeout/black-hole,
     malformed settings, proxy failure, and SSH-jump credential errors.

     3. Harden RFB parsing and encoding/clipboard resources

     - Apply DecodeLimits to protocol banner/reason/name lengths, ServerInit
     dimensions and framebuffer allocation, rectangle counts/geometries,
     colour-map counts, DesktopSize reallocations, CopyRect source/destination
     bounds, and every encoding’s pixel allocation.
     - Bound ZRLE compressed input and decompressed output, detect no-progress
     loops, reject output exceeding both configured and geometry-derived bounds,
     and reset/close only the affected session. Preserve the persistent zlib
     stream behavior and existing regression tests.
     - Make ExtendedClipboard parsing return an error for
     malformed/truncated/oversized compressed bodies instead of silently
     accepting an empty payload; enforce per-format and aggregate limits with
     checked arithmetic. Validate outgoing clipboard sizes before converting to
     signed lengths.
     - Add malformed corpus/property-style tests for each length and encoding
     path, including decompression bombs, truncated streams, invalid CopyRect,
     huge dimensions, rectangle floods, and no-progress zlib input. Ensure tests
     assert no panic and no unbounded allocation.

     4. Secure and supervise the relay

     - Port the authenticated handshake pattern from src-tauri/src/rdp/ws.rs:
     return a cryptographically random one-time token, require a VNC-specific
     WebSocket subprotocol/path, validate Tauri/debug origins, enforce one
     successful client, reject unauthorized/second clients, cap message
     sizes/rates, and never log the token.
     - Tighten tauri.conf.json CSP to the application’s required sources plus
     loopback WebSocket connections; verify dev and release origins remain
     supported without leaving CSP disabled.
     - Replace both VNC unbounded channels with a bounded priority queue. Keep
     key/button/clipboard/resize/disconnect control messages reliable, coalesce
     pointer moves, batch rectangles into logical frames, retain only the newest
     pixel frame when the consumer is slow, and record drop/high-water metrics.
     Adapt the RDP WsOutgoingQueue design while keeping VNC’s protocol types.
     - Add frame IDs, framebuffer generation/resize metadata, rectangle count
     and payload bounds to the relay wire protocol. Send a full-frame recovery
     request after a dropped/inconsistent frame. Make rendered ACKs represent
     completed Canvas drawing, not merely receipt; avoid frame-buffer growth in
     VncPanel.
     - Add a cancellation reaper in vnc_connect matching RDP session cleanup,
     and ensure relay/listener/socket/tasks/queues/capability token are released
     on every exit path. Remove clipboard previews and payloads from
     Rust/frontend logs; diagnostics may record only direction, format, byte
     count, result, and optional hash prefix.
     - Add relay tests for token/origin/path rejection, token single-use,
     second-client rejection, oversized messages, queue replacement/coalescing,
     ACK/drop recovery, idle timeout, cancellation, and session-map cleanup.

     5. Correct resize and Windows input behavior

     - Separate server DesktopSize from client-local Canvas fit.
     Validate/atomically publish remote framebuffer size and coordinate
     generation to the frontend. Only send RFB SetDesktopSize when capability
     negotiation proves support; otherwise do not advertise or imply remote
     resize. Update feature-list.md accordingly.
     - Keep remote framebuffer coordinates, Canvas backing pixels, CSS size, and
     devicePixelRatio separate. Ensure 100–200% Windows scaling and
     multi-monitor CSS changes never rewrite remote coordinates; add
     deterministic coordinate tests for fit/1:1, letterboxing, resize races, and
     out-of-range input.
     - Expand vnc.ts keysym conversion to left/right modifiers, locks, F1–F24,
     navigation, keypad, Win/Meta, AltGr/dead-key-safe behavior, Unicode code
     points, and validation of incoming JSON/frame headers. Add a
     pressed-key/button registry in VncPanel and release every pressed input on
     blur, visibility change, detach, reconnect, unmount, and WebSocket close.
     Enforce view-only in both UI and backend control dispatch.
     - Add clipboard direction policy (disabled, client-to-server,
     server-to-client, bidirectional), text-only/HTML/RTF flags, size caps, and
     safe native/fallback capability reporting. Never render remote HTML/RTF
     into the DOM; preserve plain-text fallback when WebView formats are
     unavailable. Add Windows-oriented ClipboardItem/CF_UNICODETEXT fallback
     tests where APIs can be mocked.
     - Add bounded frontend render mailbox/drop-oldest behavior, no-op invalid
     frame handling, and tests for actual draw-before-ACK, queue bounds,
     disconnect cleanup, pointer coalescing, key release, clipboard policy, and
     reconnect.

     6. Complete connection routing and detach safety

     - Pass saved VNC network settings and options from session configuration
     through MainLayout, Tab/VncPanel, IPC, and detached payloads exactly as RDP
     does.
     - Add VNC to the handleQuickConnect route, including vnc://user@host:port
     parsing and the existing credential/vault prompt path. Add tests showing
     saved and QuickConnect flows share the same auth/network/options path.
     - Replace password-bearing generic VNC detach handoff with a backend
     session capability/short-lived in-memory claim, or at minimum a redacted
     payload that forces a fresh vault resolution in the new window. Ensure no
     VNC password is written to localStorage/sessionStorage, including failure,
     popup-blocked, reattach, and TTL cleanup paths. Add static secret-leak
     scans and detached-session tests.

     7. Diagnostics, compatibility declarations, and release gates

     - Add per-session correlation IDs and bounded diagnostics for stage
     timings, negotiated protocol/security/encodings, dimensions, bytes,
     frame/rectangle/decode/render latency, queue drops/high-water,
     resize/clipboard/reconnect outcomes, and sanitized close reason. Expose a
     minimal connection-details/diagnostic view and a redacted export command if
     existing diagnostics infrastructure supports it.
     - Update qa-ui-auto-tests/feature-list.md and VNC UI copy to remove the
     false automatic SetDesktopSize/Tight/TLS claims and state the supported
     Windows 11 matrix and limitations.
     - Add a deterministic in-process RFB fixture under src-tauri/tests/support
     plus protocol integration tests for RFB 3.3/3.7/3.8, None/VNCAuth,
     ServerInit, all supported encodings, DesktopSize, clipboard, input,
     malformed data, disconnect, and timeout. Add relay integration tests using
     tokio-tungstenite and a fake WebSocket client.
     - Add frontend tests for src/lib/vnc.ts, src/stores/vncStore.ts, VncPanel,
     quick-connect, detached handoff, and network settings propagation. Replace
     scaffolding-only assertions in TC-106/107 with fixture-backed behavior
     where the QA runner can launch the fixture; retain clearly labelled
     scaffolding for cases requiring Tauri/WebView2.
     - Add scripts/CI checks for Rust tests, frontend tests/build/typecheck, fmt
     check on edited Rust files, clippy for the relevant library, malformed
     corpus, secret/log scans, QA lint/audit/dry-run, and pnpm tauri build 
     --debug --no-bundle compilation. Add a Windows-only release smoke entry
     point that is ready for a signed WebView2 package but does not falsely pass
     in browser mode.

     Verification

     Run after implementation (with the repository’s normal Windows toolchain):

     1. pnpm exec vitest run (including new VNC
     utility/store/panel/quick-connect/detach tests), pnpm exec tsc -b, and pnpm
     build.
     2. cargo test --manifest-path src-tauri/Cargo.toml --lib vnc:: plus new VNC
     integration tests; run cargo fmt --manifest-path src-tauri/Cargo.toml 
     --check and targeted cargo clippy --manifest-path src-tauri/Cargo.toml 
     --lib -- -D warnings.
     3. Run the deterministic RFB/relay fixture suite, malformed corpus,
     timeout/cancellation tests, authenticated WebSocket tests,
     queue/backpressure tests, clipboard limit tests, and credential/log static
     scans.
     4. Run QA UI lint/audit/dry-run and fixture-backed VNC cases if the local
     QA runner supports them; record any unavailable fixture/runtime explicitly.
     5. Run pnpm tauri build --debug --no-bundle (or the project’s
     Windows-compatible equivalent) to validate Tauri wiring and release
     compilation.
     6. Use a Windows 11 WebView2 signed-package/manual checklist for the cases
     that cannot be proven here: real VNC server compatibility,
     CF_UNICODETEXT/CF_HTML/RTF native clipboard, 100/125/150/200% DPI and
     monitor transitions, Win/AltGr/IME/keypad layouts, lock/sleep/wake/network
     switching, code-signed installer behavior, and long soak measurements.
     These remain the only deferred validations and must be called out in the
     final report with exact commands/results for everything else.
